## 2. Windows 构建环境

在项目根目录的 PowerShell 中执行：

```powershell
. .\Set-DevEnv.ps1
.\gradlew.bat build
```

需要开发启动时另行执行：

```powershell
.\gradlew.bat runClient
```

启动独立服务端前必须自行阅读并接受 Minecraft EULA；脚本不得代为接受。不要让客户端与独立服务端同时修改同一世界或日志目录。

### 本机 JDK 与代理

- `Set-DevEnv.ps1` 在当前 PowerShell 会话设置 JDK 和代理，不修改 Windows 用户级或系统级环境变量。
- 现有 Gradle 启动 JDK 路径为 `C:/Program Files/Java/jdk-21`。
- Java 17 toolchain 路径为 `.tools/jdk-17.0.20.1+1`（Eclipse Temurin，Windows x64），脚本通过 `JAVA17_HOME` 暴露给 Gradle；本地 JDK 不纳入 Git。
- 迁移机器后调整 `Set-DevEnv.ps1` 的 `JAVA_HOME` 和 `JAVA17_HOME`。仓库的 Gradle 属性不再固定 Windows 绝对路径。Gradle 使用 Java 21 不代表 Mod 可以使用 Java 21 API。
- 代理需监听 `127.0.0.1:7897`。脚本设置 `HTTP_PROXY`、`HTTPS_PROXY`、`NO_PROXY` 及 Java 实际使用的 `GRADLE_OPTS`；不能只依赖 HTTP 环境变量。CI 不加载本机脚本。
- `NO_PROXY` 包括 localhost、回环地址、`*.local` 和局域网网段。首次依赖下载需要可用网络；离线缓存不完整时不能完成构建。

若 PowerShell 执行策略阻止本地脚本，可仅对当前会话设置：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
```

### Make 与 IDE

已安装 GNU Make 时：

```text
make             # 默认 build，执行本地测试并生成重混淆发布包
make package     # build 的别名
make rebuild     # clean build，清理后重新打包
```

各目标在同一个 PowerShell 进程内加载 `Set-DevEnv.ps1`，无需提前加载。发布包由 `jarJar` / `reobfJarJar` 生成；普通 `jar` / `reobfJar` 对应 `-plain` 包。

IntelliJ IDEA 用 Gradle 导入项目，Gradle JVM 选择 JDK 21，项目 SDK 选择 JDK 17。Kotlin 开发优先使用 IntelliJ；Eclipse 可以生成 Forge 启动配置，但 Java 编辑器本身不提供完整 Kotlin 支持。

```powershell
.\gradlew.bat genIntellijRuns genEclipseRuns
```

Forge 开发模式统一使用 `build/modClasses/<sourceSet>` 存放 Java、Kotlin 和资源。不要只将 Java 输出加入启动配置，漏掉 Kotlin 类或 `mods.toml`。

## 3. 打包与发布注意事项

- `build/libs/ai_factory-<mod_version>.jar` 是正式包，包含 JTokkit 1.1.0 的 Jar-in-Jar；`build` 依赖 `jarJar`，后者由 `reobfJarJar` 重混淆。
- 带 `-plain.jar` 后缀的包缺少 Tokenizer，不用于发布。不要仅重命名它来冒充正式包。
- AE2、GuideME 和 Kotlin 运行库不内嵌。客户端与服务端安装 KFF；使用 AE2 拓展时另安装 Forge AE2 15.4.11 与 GuideME 20.1.7。
- 发布前修改 `gradle.properties` 中的 `mod_version`，然后重新构建。重命名 JAR 不会更新 `mods.toml` 或 manifest 中的内部版本。
- `processResources` 展开 `mods.toml` 和 `pack.mcmeta` 的变量；检查发布包时核对展开后的值、Kotlin 类、资源及内嵌依赖。
- 项目采用 [Apache-2.0](../LICENSE)，根目录 `LICENSE` 随正式 JAR 打包。JTokkit 的 MIT 许可位于 `META-INF/licenses/jtokkit-LICENSE.txt`。
- `LICENSE.txt`、`CREDITS.txt`、`changelog.txt` 是 Forge MDK 随附的许可、归属与历史文件，不是 AI-Factory 的产品更新记录。
- `.env`、模型密钥配置、JDK、开发世界和日志均不是发布附件。Git 忽略规则不能清除历史上已提交的秘密。

建议在版本改动后执行：

```powershell
. .\Set-DevEnv.ps1
.\gradlew.bat clean build
```

之后使用这个最终 JAR 在普通启动器实例中验收。构建成功或 `runClient` 可用，不等于非开发环境发布包已经通过验证。

## 4. LLM Provider 契约与易错点

抽象位于 `com.rcdiamond.aifactory.client.llm`，OpenAI 实现位于 `client.model_provider.openai_completion.OpenAICompletion`。`ModelProvider` 不是 SAM 接口：

```kotlin
suspend fun generate(prompt: LLMContext): GenerateResponse
suspend fun generate_stream(prompt: LLMContext): Result<Flow<Result<AssistantEvent>>>
```

### 上下文与请求

- `LLMContext` 包含 `systemPrompt`、有序 `globalPrompt`、可空 `tools` 和 `messages`。`ChatMessage` 包括 User / Assistant / Tool；Assistant 支持可空文本和多个 ToolCall。
- 工具定义的 `parameters` 与工具调用的 `arguments` 在 IR 中为 `JsonElement`；OpenAI wire format 的工具参数是 JSON 字符串。Provider 只处理协议，不执行工具。
- `Usage` 使用 `ULong`；`FinishReason.Unknown` 保留未知终止原因原值。
- `OpenAICompletion(baseUrl, apiKey, model)` 使用 Java 17 `HttpClient`。`baseUrl` 保留调用方的路径，仅去除末尾斜杠并追加 `/chat/completions`，不自动补 `/v1`。
- 请求顺序为主 system 消息、各 globalPrompt 的 system 消息（文件名、换行和正文）、历史消息。`tools` 为 null 或空时不发送该字段。
- `generate` 读取第一个 choice，解析文本、工具调用、终止原因及可选 usage。工具执行后，由调用方将 Assistant 调用及对应 Tool 结果加入历史，再次请求模型。

### 流式响应与取消

- `generate_stream` 返回冷 Flow；每次 collect 发起独立请求，不 collect 就不建立连接。
- 使用 `stream=true`、`stream_options.include_usage=true` 和 `Accept: text/event-stream`。兼容服务商也需要接受这些协议选项。
- SSE 解码处理 UTF-8 跨分片、LF/CRLF/CR、注释及多行 data，只消费 choice index 0。
- `AssistantEvent` 包括 `TextDelta`、`ToolCallDelta`、`Finished` 和 `TokenUsage`。工具调用片段按 index 累积；arguments 拼接完成后再解析，不能逐片段解析 JSON。
- `finish_reason` 不代表流结束，后面仍可能有 usage；继续收集到 `[DONE]`。缺少 `[DONE]` 或 finish_reason 属于协议失败，部分输出不能当作完整成功。
- Provider 不缓存完整回答、不执行工具。外层 Result 表示请求构造是否成功；HTTP、网络和协议失败以末尾失败项结束 Flow。
- 流式 API 错误使用 `LLMAPIError` 下的 `OpenAIHttpException`、`OpenAIProtocolException`、`LLMTransportError`，不附带上游响应体或敏感异常原因。
- 非流式 HTTP 非 2xx 抛 `OpenAIHttpException`；协议或工具参数 JSON 错误抛 `OpenAIProtocolException`，网络错误直接传播。不自动重试。
- 协程 await 与有背压 HTTP Publisher 不阻塞调用线程。取消会终止在途请求或订阅，`CancellationException` 不包装为普通 Result.failure。
- 默认连接超时 20 秒，HTTP 请求超时 120 秒；流式响应头之后的完整收集时限由调用方管理。
- 网络请求不访问游戏状态；游戏结果仍须在正确线程应用。公共入口不初始化 Provider、不发模型请求。

## 5. 游戏配置、工具与会话边界

玩家配置和第一次使用步骤见双语 README。开发客户端对应 `run/config/ai-factory/`，使用 Forge 已提供的 NightConfig TOML，不从仓库 `.env` 读取运行配置。

- `model.toml` 保存 `base_url`、`api_key`、`model`；密钥为明文。Git 忽略 `**/config/ai-factory/model.toml`，分享整合包、截图或日志前仍需人工检查。
- `agent.toml` 保存系统提示、步骤上限和超时。默认最多 8 步，模型请求 120 秒，工具 15 秒；已有配置不自动覆盖。
- `give_item` 只给予请求玩家本人，数量 1–2304，要求权限等级至少为 2。拒绝空气、NBT、自定义命令和其他玩家目标；背包不足时溢出物品落在玩家脚边，部分交付如实反馈。
- `execute_command` 支持有或没有开头 `/` 的命令，以请求玩家的权限、位置、朝向、维度执行，`@s` 指向该玩家，不提升权限。命令可影响世界和其他玩家。
- 命令最长 32767 字符，拒绝空白、多行、NUL 和重复开头 `/`；反馈最多 8192 字符。结果含 `command`、`success`、`result_code`、`message`、`output_truncated`，结果码 0 本身不代表失败。
- 嵌套／多目标命令的 success 表示至少一个节点成功；延迟动作、无同步反馈或聊天频道消息不能作为完整效果报告。已经生效的操作不会回滚。
- 旧 `agent.toml` 若仍声称“仅影响自己”，需人工改为以玩家身份执行、可影响世界和其他玩家后重载，不能依赖生成器覆盖旧文件。
- 普通 G 键聊天关闭时取消回合，断线清理会话及等待中的请求；取消或超时不能撤销服务端已经执行的操作。界面不暂停游戏。

AE2 细节以[交付说明](AE2智能存储拓展交付说明.md)为准：

- 智能元件五档容量，每张最多 8 个会话，共享额度；1 ME 字节对应 32 个本地 `cl100k_base` 存储 Token，256K 合计 8 Mi 存储 Token，不等于模型上下文窗口或 API 账单。
- ME 智能终端是线缆上的 Part，需要一个通道及供电，待机能耗 1 AE/t；旧终端方块不迁移。
- 上下文保存在世界存档，客户端按 UUID / SHA-256 复用或更新本地缓存，使用自己的模型配置执行 ReAct。
- ME 会话只提供库存、物品详情、合成预览、实际合成与样板管理五项工具，不提供普通助手的给物品／命令工具。合成产物留在网络中；样板编码投放可能消耗空白样板或重编码已有样板。
- ME 界面关闭不取消回合，HUD 显示后台状态；保存确认、回合结束、界面关闭后才释放锁。共享会话重载保留历史，不等于普通助手重载时的会话重置。
- 当前普通游戏操作频道协议为 `2`，共享会话协议为 `5`，客户端和服务端须同时更新；历史工具结果不重放游戏操作。

## 9. Integrated Dynamics 独立终端与只读 Agent

### 实现与包边界

- 按需求放在 `com.rcdiamond.aifactory.addon.ae2.integrated_dynamics`；包名嵌套不代表 AE2 依赖。公共入口只在 `integrateddynamics` 已加载时按类名反射初始化；该集成不导入 AE2 API。
- `IntegratedDynamicsTerminalBlock` 继承 ID 的 `BlockWithEntityGuiCabled`，方块实体继承 `BlockEntityCableConnectable`，通过原生 `NetworkElementProviderConfig.CAPABILITY` 提供位置型网络元素。连接、邻居变化、分网、卸载与重验证沿用 ID 生命周期，不查询任意相邻线缆来冒充成员关系。
- `resolve` 从本方块的 `NetworkCarrierConfig.CAPABILITY` 取得实际网络；BE 基类没有直接的 `getNetwork()`。读取 Forge `LazyOptional` 先 `resolve().getOrNull()`，不向非空 `orElse` 参数传 `null`。
- 完整方块定位为 `{kind:"integrated_dynamics",dimension,x,y,z}`，不复用 AE2 线缆部件的 `side`。服务端校验实际玩家、同维度、已加载且未移除的实时方块实体身份、原版交互权限和初次访问的 8 格距离。后台持锁访问只放宽距离。潜行扳手拆除也检查权限及距离，不要求网络仍连接。
- 只读终端不搬运资源，网络成员消耗为零，没有可配置优先级／通道；原生必需的旧配置钩子明确标为弃用。

### 会话与 Agent

- 方块 NBT 保存 `TerminalId` 和 `SessionIds`；后者为 UUID int-array 列表，最多 32 个引用。`addSession`／`removeSession` 标记变化，`hasSession`／`sessionCount` 不复制集合，`sessionIds` 提供只读快照。
- `getSession(UUID)` 仅在服务端通过实际终端身份、引用及会话所属 terminal UUID 查找。正文由 `IntegratedDynamicsSessionSavedData` 写入主世界 `ai_factory_integrated_dynamics_sessions`，不是 ME 元件或 ID 变量 ID。
- 独立存储复用 `SharedContextCodec` 的规范化、哈希、Token 计数和深度校验；每个上下文上限 4 MiB。保存／删除要求当前哈希，自动标题只能首次替换。损坏或不支持的文档原样保留并拒绝读取／修改，不覆写成空存档。
- 服务端 ID 持有独立 `SharedSessionLeases` 实例；玩家退出或服务器停止释放锁。租约保护工具和保存请求；释放请求即使终端已卸载或断网也不授予任何读取权限。没有跨方块实体与 SavedData 的磁盘事务：异常退出可能丢失尚未世界刷盘的更改。
- 正常掉落用 `minecraft:copy_nbt` 将两个 UUID 键复制至物品 `BlockEntityTag`，放置后恢复引用；正文不打包进物品。中键默认复制不声明复制会话。实际掉落／移动行为仍需游戏验收。
- `SharedAgentSessionRuntime` 抽出原共享客户端生命周期；`ClientSharedSessionRuntime` 和 `IntegratedDynamicsAgentRuntime` 分别实例化，不共享活动会话、上下文、协程或工具集。共用 Provider 配置、上下文格式、传输与界面逻辑，不让 ID 假扮 ME 元件。展示模式的所属存储字段为 `storageId`；ME／ID 线字段分别仍为 `cellId`／`terminalId`。
- `SharedSessionNetwork` 提供互不重叠的端点前缀；ID 使用 `id_`，共享协议为 **6**。终端打开事件根据 `kind` 选择运行实例；请求 UUID 统一交给 RPC 等待表，HUD 分别显示两类后台会话。

### 工具合同与依赖

- `id_network_info`：原生网络统计与材料组件；变量数是已加载容器中可解析的唯一变量定义数，不是物理卡片数量。

## 10. 共享解释器、ID DSL 与原生制卡

### 设计与代码边界

- 先提交已有 ID 工作，再落盘[实施计划](./解释器与DSL实施计划.md)，分别使用框架、DSL 设计、纯编译、原生卡片、CI 和边界修正 worktree。共享接口冻结后并行实现，由集成工作树统一验证；不让多个写入者修改同一文件。
- `com.rcdiamond.aifactory.lang` 是全 Mod 可复用的纯 Kotlin 模块，不依赖 Minecraft／Forge／ID。提供带位置的语法、单态绑定／前向引用／环检测、宿主类型与原语、确定性 typed IR、backend SPI 和有预算的纯求值器；不是完整 Haskell。
- ID DSL 注入固定 `1.31.3` 算子合同，把共享 IR 降为 value/native/call 计划，**不运行纯求值器来模拟世界**。完整[语言与后端设计](./IntegratedDynamicsDSL设计.md)、[玩家使用指南](./IntegratedDynamicsDSL使用指南.md)、[共享框架 API](./共享类Haskell解释器.md)和[固定版本源码核对](./IntegratedDynamics研究笔记/id-dsl-native-source-audit.md)各有对应文档。
- Agent 新增 `id_compile`／`id_make_cards`；机制 RPC 为 `id_describe_inputs`／`id_create_cards`。后者只收有界 plan，不收源／AST／sourceMap。现有会话上下文仍可能将 source 作为不透明对话数据保存到世界、发送给 LLM；不能声称服务端从未接收源码。
- 共享会话协议升级为 **7**，两端需同版。服务端沿用 ID 会话锁、终端身份、网络与交互权限，不因为客户端 plan 声称有类型就授予访问。

### 类型、资源和失败语义

- 不读取实时变量值；现有变量／Aspect／Proxy／Delay 的类型从原生定义和固定合同证明。未知 List 元素或 Fn 签名拒绝，不用源码注解、Any 或默认空值兜底。
- 数字不隐式提升；函数及含函数的嵌套列表没有默认相等性。已知无限列表进入全遍历消费者报错，无法证明有限时明确警告。
- 共享 typed IR 额度 **8192** 与实体定义卡额度 **256** 分离；两个各 256 元素的静态列表是两张值卡。所有不同值卡的物化 JSON 节点合计 **4096**，计划 **256 KiB**／原始 JSON 深度 **64**；同一字面值复用不重复扣额度，值内部重复子树仍按序列化次数计。
- 服务端在 schema 解码前有界计量 JSON，不能先 `toString()`；随后独立重算类型／拓扑／有限性，核对真实注册表、资源、SNBT，再预检背包。资源必须 `containsKey` 后取值，不能把不存在的 Block／Fluid 静默变为默认空气／空流体。
- 新卡只消耗无任何非空 NBT 的原生空白卡；每张拆成 count=1，用真实 handler／facade 分配 ID 并写入主背包。36 槽预检优先耗尽小堆，正确计入释放的原槽；不覆盖既有卡，不创造模式绕过，不自动安装或接物流。
- 预检失败不消耗卡／ID；开始写卡后不承诺回滚，错误保留已创建卡及 node/input。客户端映射源码行列，UI 中英文显示错误码、位置与消息；超时／取消后应先查背包，不盲目整批重试。
