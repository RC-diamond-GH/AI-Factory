# 共享解释器与 Integrated Dynamics DSL 实施计划

## 目标与边界

现有改动先保存为提交 `6539ef3`。在现有 ID 终端、独立会话与 `id_*` 查询工具上实现可执行的 DSL 编译/制卡路径，不替代 ID 原生求值器，不实现完整 Haskell。已有《IntegratedDynamicsDSL设计》是起点，所有语言变更必须同步说明原因与真实原生映射。

## 分阶段闭环

每个交付切片遵循：规划 → 分支/独立 worktree → 小提交 → PR CI → Code Review → 修正 → 合并 → 主分支 CI。CI 使用 Gradle 启动 JDK 21、编译/测试工具链 JDK 17，执行不调用付费 API 的 `build`，保存测试报告和可发布的重混淆 JAR。构建不等于游戏内验证。

1. CI 与基线：配置 pull_request、main push、手动触发的构建；记录 Code Review 与合并规则；提交并通过 PR 合入基线。
2. 共享框架：纯 Kotlin、无 Minecraft/Forge/ID 依赖的类 Haskell 词法/语法、源码位置、类型合同、依赖与诊断，以及可扩展的解释/图构造接口。覆盖函数应用、列表、条件、命名绑定、前向引用和错误边界；不引入通用 IO、递归或模块系统。
3. DSL 设计复核：独立设计 worktree 深查固定 ID 1.31.3 源码的 facade、serializer、Operator、卡片 ID 与库存行为，修订规范并给出完整用户文档。设计与共享框架互不依赖。
4. DSL 编译：基于共享框架提供明确类型的 ID 原语目录、确定性拓扑卡片图、输入合同、源映射、资源限制与分阶段诊断。动态值留在 ID 求值，不在编译期拍快照。
5. 原生制卡：服务器仅接收有界结构化计划，独立核验网络权限、外部引用、类型、原生运算与字面量，然后以原生 facade 路径生成真实卡片。消耗真实空白卡并核验背包容量；不覆盖已有变量、不隐式执行物流或配置部件。
6. Agent 接入：提供编译预览与显式制卡工具，复用现有会话租约和传输，返回阶段、错误代码、源码行列/节点与可操作提示。更新 Agent 指南与工具可发现性。

## 并行所有权

- `AI-Factory-haskell` / `feat/haskell-framework`：共享语言框架、相关行为测试及框架文档。
- `AI-Factory-dsl-design` / `docs/id-dsl-design`：ID 机制研究、语言设计和 DSL 用户文档，不改产品代码。
- 主工作区：CI、PR 合并、接口集成；待框架接口冻结后分配 DSL 编译与原生制卡两个独立 worktree。
- 同一文件只有一个实现所有者；子代理不运行中途构建/格式化，集成后统一检查。

## 验收证据

- 真实执行共享解释器与 DSL 编译路径：成功示例、部分应用/组合、动态列表、类型冲突、循环、未知名称、数值边界、无限列表消费者、源码定位与规模限制。
- 服务端计划验证有独立的输入/引用/类型/资源核验；失败不返回伪造卡片或成功结果。
- 运行默认测试与 `build`，检查发布 JAR 的 Kotlin 类、展开元数据、DSL 文档所述功能；CI 与审查结论可追溯。
- 按项目约定不启动 Minecraft 客户端/独立服务端，不接受 EULA。实际游戏内制卡、原生持续求值与非开发安装加载由使用者手动验收，不宣称已通过。

## Addon 包归属整理

- Integrated Dynamics 是独立联动，主源码和测试直接放在 `addon/integrated_dynamics`，与 AE2、JEI 平级；不因共享传输而嵌入 `addon.ae2`。
- 一次迁移 package、imports、全限定引用、公共入口的延迟反射类名与文档，不保留旧包兼容层；不改注册、资源、存档、协议或 DSL 合同。
- 验收包含迁移后的真实编译／验证路径、新入口反射方法解析、发布包新类路径及旧类缺失、既有行为测试，并继续执行 PR CI → Code Review → 合并 → main CI。不启动游戏，不把类解析视作游戏加载通过。
